# SPEC：验收标准（草案 v0）

状态：草案，2026-09-23。由 PLAN.md 的验收对照表展开，Phase 0 末尾用 Grill Me 逐条确认；标着“待定”的地方等最后一节的问题有了答案再定稿。

每条标准都写成可以核对的形式，并注明证据：**测试**（自动化，默认测试集里跑）、**演示**（录屏或现场操作）、**记录**（卷宗时间线、Git 历史或侦察文档）。

## 待定问题（Grill Me）

每个问题后面是它影响的标准。回答后把结论写进对应条目，删掉“待定”。

1. 手机：你用 iOS 还是安卓？验收要两台设备，另一台从哪里来？（S-MOB-1）
2. 部署：有没有云服务器，在境内还是境外？是否接受 Tailscale，或者有备案的域名？（S-MOB-3、S-OPS-2）
3. 推送：手机上已经装了飞书、企业微信、ntfy、Bark 中的哪几个？（S-MOB-4）
4. 模型：用哪家？是否允许把脱敏后的邮件片段发到境外模型？每月预算上限是多少？（S-DB-5、S-OPS-4）
5. 邮件分拣：哪些邮件需要起草回复（导师、课程、行政、通知），哪些永远不碰？（S-MAIL-8）
6. 时效：新邮件到推送 5 分钟内是否合适？夜间要不要免打扰？（S-MAIL-1）
7. 邮件确认：发给老熟人的常规回复（R2）是否需要“确认后 10 秒内可撤销”的窗口？（S-MAIL-3）
8. ehall：你最常办的 3 个事务是什么？哪个最适合作为第一个 D 级全自动事务？（S-EH-3）
9. vault 初始资料：有哪些（在读证明、成绩单、证件照……）？哪些字段标为 secret？（S-DB-1、S-DB-5）
10. 纠正：你希望在哪里纠正（手机卷宗页、命令行）？规则的适用范围要多细？（S-GROW-1）
11. 失败处理：连续失败几次就暂停并推送？（S-OPS-3）
12. 公开仓库：Phase 4–5 的事务 Spec 和靶场页面会带上学校页面的选择器与接口。它们跟代码一起公开，还是放进私有数据仓库、代码只留通用引擎？（S-OPS-6、S-EH-3）
