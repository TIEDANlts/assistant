# ADR 0006：Agent 运行器是端口，默认用内置最小工具循环

- 状态：提议（模型与接入方式待验证 6 确定）
- 日期：2026-09-23
- 关联：PLAN.md「架构与关键决策」、Phase 0 验证 6、Phase 6

## 背景

开放任务（起草邮件、比对材料、探索新事务）需要模型调用工具。助手要在服务器上无人值守运行、能换模型、能用假模型测试。

## 决策

- AgentRunner 是端口：`run(task, tools, budget)`，返回结果、问题或提议。
- 默认实现是约两百行的内置循环：调用模型 → 执行工具（只读工具与“提议”工具）→ 把结果写回卷宗；每次运行限步数、token 和时长。
- 结构化输出一律用 Pydantic 校验。Anthropic 接口用强制工具调用（`tool_choice` 指定唯一工具，`input_schema` 由 Pydantic 生成）；OpenAI 兼容接口用 JSON 模式。校验失败时把错误信息回传，重试一次；仍失败则转人工。
- 现成的编码 Agent 可以通过 MCP 使用同一套工具，主要用于开发期探索和沉淀新事务。

## 后果

- 能在服务器运行、能换模型、能用假 LLM 做确定性测试。
- 代价：工具循环、预算控制和重试策略要自己维护（范围小，可控）。

## 放弃的方案

- 依赖某个桌面 Agent：需要窗口开着，不能在服务器上跑，难以测试。

## 待验证

验证 6（`spikes/llm_probe.py`）：选定模型与接入方式（官方 SDK 或 OpenAI 兼容接口）；结构化输出一次通过率；单次耗时与费用。另需确认：能否把脱敏后的邮件片段发往境外模型（写入 SPEC 待定问题）。Anthropic 官方也提供原生的 JSON 结构化输出，可在验证 6 中与强制工具调用对比后再定。
