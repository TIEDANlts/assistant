# ADR 0004：对账循环（tick）+ 可恢复工作流

- 状态：已接受
- 日期：2026-09-23
- 关联：PLAN.md「核心模型」、Phase 1

## 背景

本机会睡眠，进程会重启，服务器会迁移；一个任务可能要等你几个小时才回答。处理逻辑必须在任何时刻中断后都能继续，且不重复副作用。

## 决策

- 一个调度循环按固定间隔 tick：拉取新输入并登记 `InboundItem`（`source + external_key` 唯一）、推进到期的卷宗、执行已确认的动作、检查超时的动作。
- 工作流是一组具名步骤，当前步骤存在 `task.step`；每个步骤返回 Next、Wait、Sleep、Done 或 Fail 之一。
- 每个步骤必须能安全重跑，靠唯一键（`InboundItem`、`Action(task_id, action_key)`）实现，而不是靠“记得别重复”。

## 后果

- 崩溃、睡眠、重启后自动补上；全部状态在数据库里，可观测、可回放。
- 代价：实时性受 tick 间隔限制。“新邮件 5 分钟内推送”的目标要求间隔不超过几分钟；如果服务器支持 IDLE，可以把 IDLE 当作提前唤醒 tick 的信号，但处理仍在 tick 里完成。

## 放弃的方案

- 常驻会话：上下文丢失后无法恢复。
- 回调链：崩溃时中间状态丢失，难以重放和测试。

## 待验证

- tick 间隔与是否使用 IDLE：看验证 1 记录的服务器能力（IDLE）与自发邮件到达收件箱的延迟。
