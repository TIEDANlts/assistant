# ADR 0001：分层 + 端口/适配器，核心不依赖任何外部系统

- 状态：已接受
- 日期：2026-09-23
- 关联：PLAN.md「架构与关键决策」「核心模型」

## 背景

助手要连接五类外部系统（smail、ehall、个人数据库、LLM、推送），入口有手机 PWA、调度循环和命令行 / MCP。这些都会变：学校系统改版、换模型、换推送通道、在本机和服务器之间迁移。实验要求助手持续运行，状态不能绑在某个 Agent 会话上。

## 决策

- 系统分四层：入口、编排（确定性工作流、Agent 运行器）、核心（任务账本、动作闸门、记忆）、适配器。
- 核心只含纯逻辑，通过端口（Protocol）与外部交互，不 import 任何外层。
- 端口按读写拆分：工作流和 Agent 只拿到 Reader；Writer 只注入给闸门的执行器。
- 每接入一个外部系统 = 一个适配器 + 一个假实现 + 一组契约测试；适配器之间互不 import。
- 边界由 import-linter 契约守护（`pyproject.toml` 的 `[tool.importlinter]`），违反即 CI 失败。

## 后果

- 整条流程可以先用假实现在测试里跑通（Phase 1 行走骨架），真实系统接入后契约测试保证行为一致。
- 换模型、换推送通道、换部署位置只改适配器与配置。
- 代价：多一层端口定义和依赖注入装配；临时脚本不能“顺手”发信，这是有意的。

## 放弃的方案

- 以某个 Agent 会话为中心：上下文随会话消失，不能在服务器上无人值守运行，副作用约束只能写在提示词里。

## 待验证

- “只有闸门能拿到 Writer”这一条 import-linter 表达不了（Writer 协议本身定义在 core 里）。Phase 1 需要补一个自定义测试，检查 Writer 实现只在运行时装配处被注入执行器。
