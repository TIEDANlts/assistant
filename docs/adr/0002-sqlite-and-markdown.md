# ADR 0002：运行态存 SQLite（WAL），知识与记忆存 Markdown + Git

- 状态：已接受
- 日期：2026-09-23
- 关联：PLAN.md「技术栈与仓库结构」「核心模型」

## 背景

数据分两类，性质不同：卷宗、事件、动作、确认需要事务、唯一约束和并发安全；个人资料、规则、技能需要人能直接读改、有历史、能审查差异。

## 决策

- 运行态存 `state/assistant.sqlite`，开启 WAL；不入库，定期备份。执行器用 `BEGIN IMMEDIATE` 领取动作。
- 知识与记忆（`vault/`、`memory/`）是带 front matter 的 Markdown，放在私有数据仓库 `assistant-data`，用 Git 管理。
- 检索索引（SQLite FTS5）是派生数据，随时可以删除重建。
- 代码仓库与数据仓库分离：代码仓库里不出现任何个人数据。

## 后果

- 纠正和技能以 diff 的形式可审查，也可以回滚。
- 唯一约束让工作流步骤可以放心重跑（ADR 0004）。
- 代价：两处存储要保持一致——卷宗只通过“路径 + 行号”引用 vault，索引可重建；SQLite 只有一个写者，因此需要单活实例（ADR 0009）。

## 放弃的方案

- 全放 Markdown：没有事务和唯一约束，做不到恰好执行一次。
- 独立数据库服务：部署与迁移成本高，单用户场景不需要。

## 待验证

- 无。Phase 1 落地表结构时补充迁移策略（`migrations/`）。
