# ADR 0007：ehall 用服务目录 + 风险分级 + 通用事务引擎 + 靶场测试

- 状态：提议（分级映射已定；登录方式与事务清单待验证 2–4）
- 日期：2026-09-23
- 关联：PLAN.md「核心模型」风险等级、Phase 0 验证 2–4、Phase 4–5

## 背景

ehall 有数百个事项，风险差异很大；页面由前端渲染，数据来自 JSON 接口；学校没有测试环境，错误提交可能无法撤回。方案里有两套等级——动作风险 R0–R4 与 ehall 事务等级 Q/D/F/X——原稿没有写明二者的对应关系（Phase 0 审查发现）。

## 决策

1. 服务目录登记所有事项，每个事项都有事务等级；未分级的按 X 处理。
2. 事务等级是动作风险等级在 ehall 上的投影。映射只维护一份，代码里的唯一来源是 Phase 1 的 `core/policy.py`：

   | 事务等级 | 含义 | 动作等级 | 确认方式 | 最高自动化级别 |
   | --- | --- | --- | --- | --- |
   | Q | 查询 | R0 | 自动 | 直接查询 |
   | D | 证明、预约类，可撤回、影响小 | R2 | 手机上看完整内容后点确认 | L2 |
   | F | 进入审批流的申请（请假、出校等） | R3 | 确认口令或 PIN | L2 |
   | X | 高危或未分级（退课、撤销、学籍、缴费、改密码等） | R4 | 没有执行代码 | L0 指引 |

   L1 的“暂存”按 R2 处理，无论事务等级。
3. 自动化级别 L0 指引 / L1 准备 / L2 全自动，升级条件见 PLAN.md Phase 5。
4. 通用事务引擎按 Spec（YAML，Pydantic 校验）执行 prepare、execute、verify、archive；X 级 Spec 不得出现 `submit` 段，加载时直接报错。
5. 靶场（`tests/fake_ehall/`）复刻侦察到的页面与接口，引擎的每个行为先在靶场上测试。
6. 侦察阶段用受保护的浏览器（`spikes/ehall_recon.py`）：拦截危险按钮和疑似写请求，原始抓包只存 `state/`。

## 后果

- 新事务只需写 Spec、少量 hook、靶场页面和测试，不改引擎。
- 危险操作在三处被挡：没有执行代码（R4）、只读模式的浏览器护栏、Spec 只能点击声明过的提交控件。
- 代价：靶场需要随学校页面改版而维护；侦察文档要跟得上。

## 放弃的方案

- 每个事务手写一次性脚本：重复、难测试、危险操作无法统一拦截。

## 待验证

- 验证 2：登录方式（验证码、扫码）、会话寿命、服务器能否访问（`spikes/ehall_login.py`）。
- 验证 3–4：服务目录导出；6–8 个事务的侦察与分级；第一个全自动事务（D 级、可撤回、你真的会用）。结论见 `docs/recon/risk-tiers.md`。
- 附件是“选择即上传”还是“随提交上传”，填写过程中是否有自动保存或暂存请求：这决定 prepare 能否完全只读（验证 4 逐个事务记录）。
- 代码仓库公开：事务侦察文档和服务目录原始数据放在私有数据仓库的 `recon/`。Phase 4–5 的 Spec 与靶场页面会带上学校页面的选择器和接口，是否公开见 SPEC 待定问题 12。

## 2026-09-23 验证进展

- 本机 ehall 与统一身份认证均返回 HTTP 200；用户手动登录成功，保存的会话可初步复用。
- 已从已登录门户的“全部在线应用”导出当前账号可见的 135 条服务，保存在私有数据仓库 `recon/catalog-raw.json`。
- 已对 6 个入口页做只读侦察：课表和成绩查询范围暂定 Q；无犯罪证明的官方指南明确院系/部门初审、保卫处复审，分为 F；空闲教室、证明书申请、居住证办理按 X 处理。没有点击申请、验证码发送、保存、导出等业务按钮，也没有选择附件。
- 在线应用目录与办事指南是两套入口；本次只补充读取一项指南，尚未完成全部映射。证明书申请的关联说明是毕业、学位遗失补证，不能按名称当作通用在读证明。
- 受保护入口的匿名访问会进入统一认证，保存会话能访问；每 0.5 分钟检查一次，约 0.02 小时后仍有效。仅为短时复用证据。
- 上述结果不代表已验证服务器部署、会话寿命、全部事务权限或提交能力；详细证据与限制见 `docs/recon/`。
